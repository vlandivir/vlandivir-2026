# Синхронизация альбомов поездок с Яндекс Диском

Страница `/trip/:secret` умеет делать одностороннюю резервную копию оригиналов в отдельную папку Яндекс Диска. Панель и все API-маршруты доступны только Google-администратору.

## Настройка

1. Создайте приложение для доступа к API в Яндекс OAuth.
2. Выдайте ему права `cloud_api:disk.write` и `cloud_api:disk.read`.
3. Получите OAuth-токен аккаунта, в чей Диск будут копироваться альбомы.
4. Сохраните токен локально как `YANDEX_DISK_OAUTH_TOKEN` и как одноимённый GitHub Actions secret. Токен нельзя добавлять в Git.
5. Опционально задайте `YANDEX_DISK_TRIP_ROOT`. По умолчанию используется `disk:/Фото поездок`.
6. Перед первым production-деплоем примените миграцию: `npx prisma migrate deploy` через локальный SSH-туннель к базе.

## Поведение

- «Создать папку и загрузить всё» создаёт папку альбома и запускает фоновое копирование всех действующих оригиналов.
- Созданная папка публикуется, а её публичная ссылка отображается в админ-панели. Любой человек со ссылкой сможет просматривать и скачивать эту копию.
- «Обновить сейчас» проверяет файлы в папке и повторно загружает отсутствующие.
- «Автоматически добавлять новые файлы» ставит новые загрузки альбома в очередь после сохранения в DigitalOcean Spaces.
- Копирование потоковое: сервер не держит оригинал целиком в памяти.
- Имя на Диске сохраняет исходное имя и получает короткий суффикс SHA-256, поэтому одинаковые имена не конфликтуют.
- Удаление файла из альбома не удаляет резервную копию на Яндекс Диске.
- Состояние синхронизации хранится в `Trip` и `TripMedia`; после перезапуска незавершённую синхронизацию можно безопасно запустить кнопкой ещё раз.
